### C4 Container Diagram

На втором уровне C4-модели система StressAware представлена как набор взаимодействующих контейнеров, каждый из которых отвечает за отдельную функциональную область. Диаграмма показывает внутреннюю структуру системы и взаимодействие её компонентов с пользователями и внешними корпоративными системами.

#### Web Application

Предоставляет пользовательские интерфейсы для всех ролей системы:

* личный кабинет сотрудника
* дашборд руководителя
* дашборд HR-директора
* рабочее место психолога
* административную панель

Web Application взаимодействует с Backend API через REST-запросы.

#### Backend API

Является центральным контейнером приложения и предоставляет REST API для клиентского интерфейса.

Отвечает за:

* аутентификацию и проверку прав доступа
* управление пользователями и ролями
* работу с индексами и рекомендациями
* обработку запросов на консультацию
* управление задачами психологов
* формирование отчетов
* взаимодействие с другими контейнерами системы


#### Integration Service

Отвечает за получение данных из внешних корпоративных систем:

* Jira — задачи, дедлайны и активность
* корпоративный календарь — встречи и рабочая загрузка
* HRIS — данные сотрудников и организационная структура

Полученные данные передаются для дальнейшей обработки и сохраняются в базе данных.

#### Stress Calculation Service

Рассчитывает индивидуальный индекс стресса сотрудника на основе данных, полученных из корпоративных систем.

При расчёте используются:

* рабочая нагрузка
* дедлайны и просроченные задачи
* количество и длительность встреч
* отклонение активности сотрудника от его обычного уровня

Результат расчёта сохраняется в PostgreSQL вместе с компонентами индекса и временем расчёта, что позволяет формировать историю изменения показателя.

#### Recommendation Service

Формирует персональные рекомендации для сотрудника на основе:

* текущего индекса стресса
* зоны риска
* факторов, оказавших наибольшее влияние на показатель

Для руководителей рекомендации формируются на основе агрегированных показателей отдела без раскрытия индивидуальных значений сотрудников.

#### PostgreSQL Database

Центральное хранилище данных системы.

В базе хранятся:

* компании
* пользователи и роли
* подразделения
* история индекса стресса
* рекомендации
* запросы на консультацию
* задачи психологов
* статусы и заметки по задачам
* настройки интеграций


### Основной поток данных

Общий сценарий работы системы выглядит следующим образом:

**Внешние корпоративные системы → Integration Service → PostgreSQL → Stress Calculation Service → Backend API → Web Application**

Integration Service получает актуальные данные из Jira, календаря и HRIS и сохраняет их в системе. Stress Calculation Service использует эти данные для расчёта индекса стресса. Полученный результат сохраняется в базе данных.

Когда пользователь открывает соответствующий интерфейс, Web Application обращается к Backend API. API получает необходимые данные из базы и обращается к сервисам расчёта или рекомендаций.

Если после пересчёта сотрудник переходит в красную зону, Backend API  проверяет наличие активной задачи психолога и при необходимости создаёт новую задачу. Психолог видит её в своём рабочем месте через Web Application.
