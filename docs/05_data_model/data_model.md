## Описание сущностей

### Company

Хранит информацию о компаниях-клиентах, использующих StressAware

**Атрибуты:**

* `id` — уникальный идентификатор компании
* `name` — название компании
* `created_at` — дата и время создания записи
* `updated_at` — дата и время последнего изменения

### User

Хранит информацию о сотрудниках компаний. 

**Атрибуты:**

* `id` — уникальный идентификатор пользователя
* `company_id` — ссылка на компанию, в которой работает сотрудник
* `email` — корпоративная электронная почта
* `full_name` — полное имя пользователя
* `department_id` — ссылка на отдел, в котором работает сотрудник
* `role_id` — ссылка на роль пользователя в системе
* `hire_date` — дата найма сотрудника
* `consent_given` — признак предоставления согласия на обработку данных
* `created_at` — дата и время создания записи
* `updated_at` — дата и время последнего изменения

### Role

Справочник ролей пользователей. Определяет доступные пользователю функции и данные.

**Атрибуты:**

* `id` — уникальный идентификатор роли
* `name` — название роли: Сотрудник, Руководитель, HR-директор, Психолог, Администратор
* `description` — описание роли

### Department 

Хранит организационную структуру компании. 

**Атрибуты:**

* `id` — уникальный идентификатор отдела
* `company_id` — ссылка на компанию
* `name` — название отдела
* `parent_department_id` — ссылка на вышестоящее подразделение

### StressScore

Хранит историю рассчитанных значений индекса стресса сотрудников. 

**Атрибуты:**

* `id` — уникальный идентификатор записи
* `user_id` — ссылка на сотрудника
* `score` — значение индекса стресса от 0 до 10
* `risk_zone` — зона риска на момент расчета: зеленая, желтая или красная
* `workload_score` — нормализованная оценка рабочей нагрузки
* `meeting_score` — нормализованная оценка нагрузки от встреч
* `deadline_score` — нормализованная оценка нагрузки, связанной с дедлайнами
* `activity_deviation_score` — оценка отклонения активности сотрудника от его индивидуального уровня
* `calculated_at` — дата и время расчета индекса

### Recommendation

Хранит персонализированные рекомендации, сформированные для сотрудника на основе его индекса стресса и факторов риска.

**Атрибуты:**

* `id` — уникальный идентификатор рекомендации
* `user_id` — ссылка на сотрудника, которому адресована рекомендация
* `text` — текст рекомендации
* `priority` — приоритет рекомендации
* `reason` — причина формирования рекомендации
* `created_at` — дата и время создания
* `is_viewed` — признак просмотра рекомендации сотрудником

### ConsultationRequest

Хранит информацию о запросах сотрудников на консультацию с психологом.

**Атрибуты:**

* `id` — уникальный идентификатор запроса
* `user_id` — ссылка на сотрудника, отправившего запрос
* `comment` — дополнительный комментарий сотрудника
* `priority` — приоритет запроса
* `status` — текущий статус запроса
* `created_at` — дата и время создания запроса
* `resolved_at` — дата и время завершения запроса

### PsychologistTask

Хранит задачи, предназначенные для работы психолога. 

**Атрибуты:**

* `id` — уникальный идентификатор задачи
* `consultation_request_id` — ссылка на запрос сотрудника, если задача создана по запросу на консультацию
* `employee_id` — ссылка на сотрудника, которому требуется внимание
* `psychologist_id` — ссылка на назначенного психолога
* `task_status_id` — ссылка на текущий статус задачи
* `stress_score_at_creation` — значение индекса стресса на момент создания задачи
* `created_at` — дата и время создания задачи
* `updated_at` — дата и время последнего изменения
* `closed_at` — дата и время закрытия задачи

### TaskStatus

Справочник статусов задач психолога.

**Атрибуты:**

* `id` — уникальный идентификатор статуса
* `name` — название статуса: Новая, В работе, Решена
* `description` — описание статуса


### Integration

Хранит информацию о подключенных внешних системах компании: Jira, корпоративном календаре и HRIS.

**Атрибуты:**

* `id` — уникальный идентификатор интеграции
* `company_id` — ссылка на компанию
* `name` — название интеграции: `jira`, `google_calendar`, `outlook`, `hris`
* `config` — параметры конфигурации интеграции
* `status` — текущий статус интеграции: активна, неактивна, ошибка
* `last_sync_at` — дата и время последней успешной синхронизации
* `error_message` — информация о последней ошибке, если она возникла



## Связи между сущностями

| Связь                                  | Тип      | Описание                                                |
| -------------------------------------- | -------- | ------------------------------------------------------- |
| Company → User                         | 1 : N    | Одна компания может иметь много пользователей           |
| Company → Department                   | 1 : N    | Одна компания может иметь много отделов                 |
| Company → Integration                  | 1 : N    | Одна компания может иметь много интеграций              |
| Department → User                      | 1 : N    | Один отдел может содержать много сотрудников            |
| Role → User                            | 1 : N    | Одна роль может быть назначена многим пользователям     |
| User → StressScore                     | 1 : N    | Один сотрудник имеет много записей индекса              |
| User → Recommendation                  | 1 : N    | Один сотрудник может иметь много рекомендаций           |
| User → ConsultationRequest             | 1 : N    | Один сотрудник может создать много запросов             |
| ConsultationRequest → PsychologistTask | 1 : 0..1 | Запрос может создать не более одной задачи психолога    |
| User → PsychologistTask (сотрудник)    | 1 : N    | Один сотрудник может иметь много задач как подопечный   |
| User → PsychologistTask (психолог)     | 1 : N    | Один психолог может вести много задач                   |
| TaskStatus → PsychologistTask          | 1 : N    | Один статус может использоваться многими задачами       |
| Department → Department                | 1 : N    | Один отдел может иметь несколько дочерних подразделений |

## Ключевые бизнес-правила, отраженные в модели

* **Мультитенантность** — данные пользователей, подразделений и интеграций принадлежат конкретной компании через `company_id`. Доступ к данным другой компании запрещен.
* **Разграничение доступа** — роль пользователя определяет доступные функции и уровень детализации данных.
* **Конфиденциальность** — руководители получают агрегированные показатели подразделения и не имеют доступа к индивидуальным значениям индекса сотрудников.
* **Хранение истории** — `StressScore` сохраняет рассчитанные значения индекса, что позволяет анализировать динамику стресса во времени.
* **Автоматическое создание задач** — переход сотрудника в красную зону может привести к созданию задачи психологу.
* **Отсутствие дубликатов** — при наличии активной задачи по сотруднику новая задача для того же случая не создается.
* **Задачи по запросу** — запрос сотрудника на консультацию может быть связан не более чем с одной задачей психолога.
* **Статусная модель** — `PsychologistTask` связана со справочником `TaskStatus`, который определяет жизненный цикл задачи.
* **Иерархия подразделений** — `Department` поддерживает структуру компании через `parent_department_id`.
