# StressAware system


**StressAware** - сервис для предиктивного мониторинга стресса сотрудников и раннего выявления риска выгорания.

Система интегрируется с корпоративными системами компании, собирает данные о рабочей нагрузке и рассчитывает индивидуальный **Stress Index**. На основе полученного показателя сотрудник получает персональные рекомендации, а HR, руководители и корпоративные психологи — инструменты для работы с рисками на соответствующем уровне доступа.

Проект выполнен как **системно-аналитический pet-project**: от анализа бизнес-проблемы и формулирования требований до проектирования API, модели данных и архитектуры системы.


## Цель проекта

Спроектировать систему, которая позволяет автоматически собирать данные о рабочей нагрузке сотрудников, выявлять изменения в уровне стресса и передавать информацию ответственным специалистам.

Целевой бизнес-эффект — **снижение текучести кадров на 15%** за счёт раннего выявления сотрудников группы риска и своевременных мер поддержки.

## Этапы работы

### 1. Анализ бизнес-проблемы

Определила проблему, заинтересованных участников и основные цели будущей системы.

На этом этапе были сформированы:

* stakeholders
* границы проекта
* бизнес-требования
* критерии оценки результата

### 2. Формирование требований

На основе бизнес-задач описала:

* бизнес-правила
* пользовательские требования
* функциональные требования
* нефункциональные требования
* Use Cases для основных сценариев работы системы

### 3. Проектирование логики системы

Определила основные правила работы StressAware:

* расчёт Stress Index
* определение зон риска
* формирование персональных рекомендаций
* ограничение доступа к данным в зависимости от роли
* создание задачи психологу при переходе сотрудника в красную зону
* предотвращение создания дублирующих задач

### 4. Проектирование данных

Разработала реляционную модель данных для хранения:

* пользователей и ролей
* организационной структуры
* истории Stress Index
* рекомендаций
* запросов на консультацию
* задач психологов
* интеграций

### 5. Проектирование API

Разработала REST API спецификацию в **OpenAPI**, которая описывает взаимодействие клиентского приложения с Backend API.

API разделено по ролям: сотрудник, руководитель, HR-директор, психолог и администратор.

### 6. Проектирование архитектуры

Сформировала архитектуру системы с использованием **C4 Model**.

Выделила основные компоненты:

* Web Application
* Backend API
* Integration Service
* Stress Calculation Service
* Recommendation Service
* PostgreSQL Database
